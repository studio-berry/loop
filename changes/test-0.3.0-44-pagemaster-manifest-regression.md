Summary: Close the measured proof gaps in issue #44 for the ADR-004 PageMaster batch manifest. UnitTestsPageMasterExport gains nine slots: a five-output batch whose third destination directory was never created is shown to mark only that output failed, with outputs 1-2 still reopening as valid PDFs, outputs 4-5 left pending and no file at the failed output's final path; a new job-level commit seam (PDFPageMasterExportJob::beforeOutputCommit, path-keyed and empty in production) lets the existing self-exec harness kill a child inside one output's staging window - the window the manifestPersist kill does not reach - and the restart is asserted to leave a parsing manifest, outputs 1-2 byte-valid, output 3 with no file at its final path, and a batch that still resumes to five written outputs under the same batch_id; resume is shown to retry an entry recorded failed, to re-run an entry recorded written whose file was deleted, and to treat a missing manifest as a fresh batch rather than an error; and manifest integrity is pinned for a path that cannot be read as a manifest, for an empty outputs array, and for two batches sharing the default .loop-batch.json in one directory, asserted as the observed aliasing rather than as a lock. Every assertion is a file-level or manifest-field observable that survives a Release build, and the kill harness exits 92/93 when its seam was armed and never fired so the scenario cannot pass vacuously. Amend ADR-004 to the code as built: schema_version 3 rather than 1, exactly the pending|written|failed statuses with no skipped, QSaveFile open/producer/commit instead of a <finalPath>.<pid>.partial file plus QFile::rename, a manifest retained after a successful batch with no completion marker, and resume's real rules (a written entry is left alone only while its file exists), with each drifted claim listed as deliberately superseded and the Last-verified stamp moved to this commit. Measured and reported but deliberately not asserted: a hard exit inside the staging window leaves Qt's own staging temp file behind, named <finalPath>.XXXXXX with six random alphanumerics (zero bytes in every observed case), which never appears at a final output path.
