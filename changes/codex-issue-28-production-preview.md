# Separate Production Preview from the fast canvas (#28)

Category: changed
Audience: prepress operators and reviewers reading render fidelity on the canvas and in the Production Preview
Breaking-Change: no
Summary: The ordinary canvas banner (now hidden for an exact fast-canvas page, with a plain-language accessible description) and the Production Preview now render one shared preview fidelity-and-origin projection. EditorHost exposes previewFidelityStateName / previewFidelityOriginName / previewFidelityVisual / previewFidelityColor / previewFidelitySummary, derived by pdfquick::tokens::classifyPreviewFidelityState from the preview state and the current page's render diagnostics, naming both the fidelity (unavailable / stale / exact / approximate / authoritative) and the render origin (none / fast-canvas / output-preview). An overprint-sensitive page on the fast canvas path is the `approximate` state; previewRequiresAuthoritative() is true exactly then, its summary states that those pixels are not proof of print-safe output, and EditorHost::ensureAuthoritativePreview() is the explicit switch the preview surfaces call before a page is presented as proof. No preview fidelity state resolves to a pass treatment. Proven by UnitTestsLoopStateVisual (classification, origin, distinct shapes, never a pass), UnitTestsEditorHost (the projection and the explicit switch on a real overprint fixture) and UnitTestsPageSurface::fastCanvasOverprintRenderIsNotTheAuthoritativeGolden (the fast render does not match overprint-cmyk-mode1-on.png while the authoritative render does).
