Category: changed
Audience: operators
Breaking-Change: no
Summary: The save policy an operation declares is now carried by every Action List step plan and every Action List execution result, and it is enforced at every write. "Preserved attributes" are the declared consequences themselves — save mode, signature invalidation, session reversibility, and rationale — not a new field, and nothing may substitute a different policy for them. A weakened `requestedSavePolicy` is refused with `action-list.save-policy-refused` before any step work (dry runs included), the merged policy is bound into the Action List plan digest, `PdfTool action-list run/batch` and the Editor publication boundary validate the save request before writing, and `PdfTool repair` now refuses `--output <source>` with `save-policy.refused` and exit code 4 even with `--overwrite` instead of publishing over the trusted input. Reviewer can check `stepPlansCarryDeclaredSavePolicy`, `executeRefusesWeakenedRequestedSavePolicy`, `repairRefusesToWriteOverItsOwnInput`, and the Policy strength section in docs/INCREMENTAL_SAVE.md. Empty-selection step plans retain the declared save policy, and batch items report a failed status and error when publication is refused by the save guard.
