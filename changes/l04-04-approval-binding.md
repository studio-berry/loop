Category: changed
Audience: operators
Breaking-Change: no
Summary: A governed approval is now current and authorized only when `pdf::resolveApprovalAuthorization()` accepts it, and every gateway function (`validateGovernedApproval`, `finalizeGovernedPublication`, `publishGovernedArtifact`, `validateGovernedSignOff`) calls it before any write. `PDFApprovalRecord` gains an optional `expiresUtc` (null = no declared expiry) and `isExpiredAt()`; an approval is refused as `approval-expired` when its expiry is at or before the evaluated time (boundary inclusive) or, under a policy that sets `requireExpiry`, when it declares none. `PDFGovernedExecutionApproval` gains an optional `effectiveProfileDigest`; when a caller supplies `PDFApprovalAuthorizationContext.expectedProfileDigest`, the approval must match it (`profile-binding`), so an approval taken against one effective profile cannot authorize a run under another. Approver rights are declared through `PDFApprovalAuthorizationPolicy` allowlists (`authorizedActorIds`, `authorizedKinds`; an empty list declares no restriction) and an approval with no actor is always refused (`approval-unauthorized`). Revocation is an append-only `ApprovalRevoked` history event whose `approval.decisionReference` matches the approval's reference (`approval-revoked`), mirroring certificate invalidation with no second registry. `PdfTool repair` and `action-list run/batch` resolve revocation against the output `.loop-history` chain; PageMaster and the Editor Action List worker have no operation-history store in scope, so their contexts leave `history` null and #37 centralizes execution to close that gap. Reviewer can check `approvalExpiryWindowIsEnforced`, `approverRightsAreAllowlisted`, `profileBindingRefusesMismatch`, `revokedApprovalIsRefusedBeforeWrite`, `revokedApprovalRefusesLaterAttempt`, `approvalExpiryAndRevocationKindRoundTrip`, and the Approval section in docs/GOVERNED_EXECUTION.md. Malformed declared expiries and unavailable or compromised revocation histories refuse publication.
