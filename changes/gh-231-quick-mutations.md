Category: added
Audience: operators and developers of the Quick shell
Breaking-Change: no
Summary: Interactive authoring edits become direct Core mutations through the one `CommandCatalog` path, per the recorded ADR-014 decision (direct revision for authoring, planned operation stays for governed Fix). Thirty-nine commands gain handlers and land as implemented — the 16 bookmark/hyperlink ids (#233), the 18 annotation ids (#234), and the four new form/attachment/metadata ids plus `actionSend_by_E_Mail` (#242, `expected_action_count` 109 → 113) — each mapping its declared scalars into one typed direct-edit request on `DocumentFacade` that checks the revision fence and the document's permission before Core writes and refuses with a typed code (stale revision, permission denied, XFA-only form, executable attachment, unsupported outline structure) instead of half-writing. Bookmarks and links round-trip through Core's outline writer with all nine destination variants serialized and read back through Core's reader, import/export as a canonical file; annotations are created per subtype with appearance streams through Core's annotation model; form values, attachments and XMP metadata go through Core writers that preserve foreign XMP properties, attachment extraction writes through the atomic writer and refuses executable auto-open, and send-by-email hands the current published revision to the mail client. Every accepted edit appends one operation-history event and rollback point (the #124 revision-history model), and the handler-coverage ratchet tightens from 48 to 13 KEEP/ABSORB commands still awaiting a handler (PR 3 takes it to zero).
