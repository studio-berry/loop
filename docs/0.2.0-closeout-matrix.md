## What this harvest closes vs. what it cannot

**Closed by real CI evidence** (3 independent full runs on both OSes — see
Q-02/Q-04 above): the S21 benchmark on the corrected required candidates, the
Windows+Linux native/software `QuickShellSmoke` scene-graph smoke, the S22
static admission substrate, and the QWidget-to-Quick-to-QWidget focus-bridge
probe (native + software, both OSes, all runs).

**Cannot be honestly closed before Phase 4 produces a shipped product Quick
module:** P-01 (clean-machine package smoke), P-02 (final-artifact SBOM/
notices/LGPL), and product Quick accessibility runtime (as distinct from the
qualification-only focus-bridge probe above). All three require an installed
artifact to inspect; at P4-S1 there is only a non-installed qualification
harness. Treat these as Phase-4-exit gates the checklist miscategorized as
pre-P4-S1 gates, and say so explicitly wherever this status is reported —
including in the Notion checklist update — rather than ticking them.

**Unrelated finding, flagged separately (not fixed here):** the same CI runs
reproducibly show `UnitTestsPreflightPlugin` and `UnitTestsPreflightCorpus`
failing on both Windows and Linux (a schema-normalization bug and a
corpus-driven test, confirmed unrelated to this harvest by diff — zero
preflight/plugin files touched by any commit here), plus
`UnitTestsPdfToolContract` failing on Linux only (`PdfTool` CLI is missing a
`checks` option a test expects). All three passed cleanly on the last full CI
run against `stable` (2026-08-20), so this is a regression that landed on
`dev` sometime after that and was never caught because `dev` pushes don't
trigger the full Windows/Linux CI jobs. Flagged as a separate follow-up task;
out of scope for S21/S22 closure.
