**Living milestone.** Former planning alias: **0.0.6**. Supersedes the retired **0.1.4** GitHub milestone title.

## Canonical name
Evidence-Grounded Correction Assistance

## Critical path
Authoritative selected finding → minimized revision-bound evidence context → deterministic offline explanation → optional validated explanation → registry-backed safe next action → deterministic finding-driven plan → existing 0.3.0 preview and operator approval.

## Objective
Help the operator understand a preflight finding, its measured evidence, incomplete/unsupported coverage, and its safely applicable correction options. Assemble an inspectable plan without creating a new technical-truth, approval, correction, or publication authority. The release is useful with no model provider and no network.

## Medic: optional cross-milestone sidecar — non-gating
**Medic** is a separate bleed-reconstruction project with its own research, specialist-selection, quality, and press-safety qualification. Medic may extend this or later Loop milestones, but Loop **0.4.0 exit completion does not depend on Medic** being implemented, integrated, available, or qualified. A future Medic adapter may offer eligible repair proposals only through Loop's existing evidence, review, approval, and publication contracts. Medic is referred to by project name, never as the name of Loop's general assistance boundary.

## Out of scope
Autonomous mutation; model-created findings, verdicts, thresholds, or conformance assertions; model approval or publication; separate provenance or correction path; 0.5.0 JobSpec, natural-language plan compilation, encrypted job spine, job-aware profile resolution, application scheduler; 0.8.0 full operator onboarding; full customer intake/MIS; internet-required workflows. No research sidecar is required for release completion.

## Authority model
Core computes technical truth. The operator authorizes consequential work. Optional inference explains and proposes from validated evidence only. Offline deterministic explanation and planning remain useful without a provider.

## Exit rule
#686 verifies the end-to-end offline and optional-provider vertical, hostile cases, and absence of authority drift on a named exact assembled SHA. Missing/stale/flaky/cancelled proof is not a pass. Medic qualification is tracked separately, never a 0.4.0 release gate.
