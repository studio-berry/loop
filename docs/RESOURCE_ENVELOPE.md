# 0.2.0 resource-envelope workload

Phase 3 qualification budgets and evidence rules are defined in
`docs/RESOURCE_ENVELOPE_BUDGETS.json` and
`docs/RESOURCE_ENVELOPE_QUALIFICATION.md`. The workload envelope uses `-1`
for unavailable measurements; such records must carry a non-success status
and reason.

The image-heavy workload source is the external deterministic DIV2K bleed
corpus generated by the `l-bleed` research repository:

`C:\.dev\repos\l-bleed\results\DIV2K`

It contains 18,000 examples from 900 source images. Each example has
`input.png`, `ground_truth.png`, `mask.png`, and `metadata.json`. The corpus is
not copied into Loupe or treated as a checked-in product fixture.

## Validate and select

Run from the Loupe repository:

```powershell
python scripts/resource_envelope/div2k_workload.py validate `
  --corpus-root C:\.dev\repos\l-bleed\results\DIV2K

python scripts/resource_envelope/div2k_workload.py manifest `
  --corpus-root C:\.dev\repos\l-bleed\results\DIV2K `
  --output C:\temp\loupe-div2k-manifest.json `
  --sample-count 256 `
  --seed 0
```

Use `--hash-all` when producing qualification evidence. It hashes the full
corpus contract; without it, the manifest hashes the selected examples while
still recording the corpus summary and structural digest.

## Build a production-scale image PDF

```powershell
python scripts/resource_envelope/div2k_workload.py build-pdf `
  --manifest C:\temp\loupe-div2k-manifest.json `
  --output C:\temp\loupe-div2k-10000-pages.pdf `
  --page-count 10000 `
  --page-seed 0 `
  --summary-output C:\temp\loupe-div2k-10000-pages.json
```

The writer embeds each selected RGB input image once and reuses those image
objects across the requested page count. Page order is deterministic and
cycles through the selected examples from the supplied page seed. The output
uses fixed PDF metadata and an ID derived from the manifest digest.

## Run the real PdfTool path

Use the rebuilt `PdfTool` with a Qt platform plugin available to the process.
For a headless Windows run, `QT_QPA_PLATFORM=offscreen` is supported:

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
$env:QT_PLUGIN_PATH = "C:\path\to\qt\plugins"
PdfTool.exe benchmark C:\temp\loupe-div2k-10000-pages.pdf `
  --render-hw-accel 0 `
  --render-rasterizers 8 `
  --console-format json
```

The JSON result includes the `workload_envelope` object. A successful
Windows software-renderer run on the local 0.2.0 candidate rendered all
10,000 pages in 48,513 ms and recorded a peak RSS of 380,985,344 bytes.
The result identity carried the PDF digest
`4877a4f821545e47d40bdae73584b5a7e091305d10661733313a8dd8d9404c65`.
This is local implementation evidence only; it is not merged-SHA or release
evidence.

This proves the image-heavy workload path. It does not replace the separate
pathological-vector workload, Linux runtime evidence, or a cancelled-run
measurement for the cancellation-latency field. Cache, pressure-shedding, and
recovery fields remain unmeasured. A benchmark
result is non-qualifying when the workload is unavailable, cancelled,
unsupported, budget-exceeded, or incomplete.
