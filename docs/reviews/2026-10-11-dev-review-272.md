# Adversarial review of the dev train promoted by PR #272

Date: 2026-10-11
Scope: `origin/unstable...origin/dev` (15fed584), 60 commits / 43 non-merge, 194 files
Method: five independent adversarial reviewers, one per subsystem slice (Core PDF mutation,
Interaction gateway, Editor/UI, gates and generated registers, tests), same rubric; findings
verified against the source before classification; the fixes land in the accompanying PR against
`dev`.

Model diversity was not available (all reviewers ran on the session model); the signal comes from
the five disjoint entry points, so agreements below mean the same defect was reachable from
different slices.

## Status of this report

Findings are labelled with the disposition of the accompanying fix PR:

- **fixed**: corrected in the review-fix PR, with a regression test where one is constructible.
- **deferred**: real, not fixed here; listed as follow-up work.
- **dismissed**: reclassified or rejected on evidence, with the reason.

## Deferred and dismissed detail

- **Deferred: history re-verification on the interactive thread (finding 20).** The revision-change
  path calls `PDFOperationHistoryStore::verify()` (a full-chain re-hash), reads the event table
  twice and issues one execution query per event, synchronously, on the thread the host registers
  as the blocking-thread-guarded interactive thread. Correct fix is to move the read into the
  existing scheduler-worker pattern; that is a restructure, not a review fix.
- **Deferred: the accessible-readout test (finding 32).** The test proves the setter, not the host
  composition. Covering the composition needs the summary built through the host (or extracted
  into a pure function); noted rather than widened here.
- **Dismissed: signature badge staleness (finding 15).** `documentfacade.h` documents that the
  facts describe the source bytes the document was loaded from and that an in-session revision
  change does not retract them; the badge wording matches that contract. The operator-visible
  defect was the wedge (finding 11) and the missing re-submission path, which the fix addresses at
  the rejection site.
- **Noted, not filed**: a duplicate `setCurrentRevision` call in the host, a late ink-coverage
  completion after document close can repopulate the readout (the outcome map is not cancelled on
  close), a retained display-filtered tile copy, `setTextSelection`'s missing `isCurrent()` guard
  (no current caller can pass a stale-but-valid token), duplicated `usableBounds` helpers in two
  files, the outline writer drops a GoTo's `/SD` (structure destination) on any rewrite (the same
  class as finding 5, outside its scope), and the translations catalogs predate the #123
  print/export strings, so the new MenuModel switch string extracts on the next `LOOP_lupdate`
  refresh.
- **Behaviour note**: `UnitTestsLoopStateVisual` now fails when the compiled catalogs are absent
  instead of skipping; the agent-fast lane builds `LOOP_lrelease` (LoopEditor depends on it), so
  the catalogs exist before the suite runs there.
